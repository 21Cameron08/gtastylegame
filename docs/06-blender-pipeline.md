# 06 – Blender Pipeline

Blender is the main content tool **and the level editor**: meshes, modular
kits, vehicles, characters, the road network, and where everything sits in the
world. This doc sets the conventions so assets load in the game with zero
manual fixing.

## How Claude works with Blender

Claude runs Blender headless in the cloud environment and drives it with
`bpy` Python scripts kept in `blender/scripts/`. Scripts generate assets,
validate them, and export compressed `.glb` files into `game/public/assets/`.
You can open any `.blend` in your own Blender to review or tweak it, and
commit it back.

Scripts are versioned and repeatable, and they run in CI. A smoke test (script
builds a mesh with a collision hull and exports `.glb`) already passes.

**Blender version**: pinned to **4.0.2**, Ubuntu 24.04's package. It's what
the cloud environment can install (blender.org downloads are blocked there) and
what CI installs, so local and CI builds match. Upgrading means changing both.

## Division of labor

**Scripted (generated by code):**
- Modular building kits: parametric brick storefronts, windows, cornices,
  awnings, porches, siding, roofs
- Road network: road meshes, curbs, sidewalks, parking lots, painted lines
- Fences, power poles with sagging lines along a curve, mailboxes, signs
  (church marquee with custom text), billboards
- Vegetation scatter sets (pines, scrub, kudzu patches)
- Blockouts for vehicles, weapons, and landmark buildings
- Cell layout export, validation, LOD checks, compression, preview renders

**Hand-authored or hand-polished (either of us, in Blender):**
- Hero vehicles and their detail pass
- Characters (body, clothes, faces)
- Weapons
- Landmarks: courthouse, water tower, SaveMore, megachurch, mill

## Units, axes, origins

- **1 Blender unit = 1 meter.** Apply all transforms (scale 1, rotation 0) before export.
- **Up = +Z in Blender.** The glTF exporter converts to +Y up, which is what Three.js uses.
- **Forward**: models face **−Y** in Blender (the Front view, Numpad 1, shows
  the front). That becomes +Z in glTF, the standard glTF forward direction.
- **Origins**:
  - Props and freestanding buildings: bottom center (sits on the ground at Z = 0)
  - Street-facing buildings: bottom center of the street facade, so facades line
    up on the sidewalk edge whatever the building's depth
  - Vehicles: ground level, centered between the axles
  - Wheels: hub center
  - Characters: between the feet
  - Weapons: grip point

## Object suffixes (read by our loader)

Three.js has no import hints of its own, so the game's glTF loader reads these
suffixes and builds physics and LOD from them:

| Suffix | Result in game |
| --- | --- |
| `-col` | Visible mesh that is also a static triangle-mesh collider (large static buildings only) |
| `-colonly` | Invisible collider. Shape from the `collider` property: `box`, `sphere`, `capsule`, `convex`, or `trimesh` |
| `-nav` | Navmesh source geometry, not rendered |
| `-lod1`, `-lod2` | Lower-detail versions, swapped in by distance |
| `-noexp` | Not exported (reference and helper objects) |

Rule: **collision is always simple.** Use a separate low-poly hull
(`-colonly`), never the render mesh, except for large static buildings.

## Custom properties

Blender custom properties export as glTF "extras" and arrive in Three.js as
`userData`. We use them for gameplay data:

| Property | Used for |
| --- | --- |
| `collider` | Collider shape for `-colonly` objects |
| `mass` | Dynamic props (bins, cones, crates) |
| `surface` | `asphalt`, `dirt`, `grass`, `mud`, `gravel`, `wood`: tire grip, footsteps, particles |
| `night_emissive` | Materials that light up at night (neon, windows, streetlights) |
| `interact` | Interaction ID (shop door, ATM, vending machine) |

## Gameplay markers (Blender as level editor)

Empties placed in a cell become gameplay markers:

| Empty name | Meaning |
| --- | --- |
| `SPAWN_PED_*` | Pedestrian spawn area |
| `SPAWN_CAR_*` | Parked or traffic vehicle spawn |
| `DOOR_*` | Enterable interior or shop entrance |
| `MISSION_*` | Mission start or objective point |
| `SAFEHOUSE_*` | Save point |

## Cells and placement

- Each 250 m map cell is its own Blender collection named `CELL_x_y`.
- Kit pieces and props are placed as **linked instances** of the shared kit
  assets. The export script writes them to the cell's placement manifest
  (asset ID + transform) instead of copying their geometry into the cell.
- Only unique geometry (terrain, roads, one-off structures) goes into the cell's own `.glb`.

## Modular grid

- Snap to a **0.5 m** grid; kit pieces are multiples of **1 m**.
- Downtown facades: **4 m** wide modules, **4.5 m** ground-floor storefronts,
  **3.5 m** upper floors.
- Houses: **3 m** floors; porches **2.5 m** deep.
- Roads: **3.5 m** lanes, **2 m** sidewalks, **15 cm** curbs.

## Materials & textures (web budgets)

- **Trim sheets** (1024² by default, 2048² for the most-seen sets) for buildings:
  brick, siding, trim, windows, signage. Most of the town shares a handful of
  materials, so it draws in few batches.
- **Palette texture** (256²) for props: UVs land on color swatches. Ideal for
  scripted assets and almost free to render.
- **Vehicles**: 1024² body texture plus a shared paint material whose color is
  set per car in code (one mesh, many paint jobs).
- **Characters**: 1024² per character; clothes share atlases.
- PBR metallic/roughness. All textures ship as **KTX2** (GPU-compressed) to keep
  downloads and GPU memory low.

## Triangle budgets (LOD0, browser targets)

| Asset | Triangles |
| --- | --- |
| Player-drivable vehicle | 10k–25k |
| Character | 8k–15k |
| Weapon | 2k–5k |
| Small building | 500–4k |
| Landmark | up to 12k |
| Prop | 50–1.5k |
| Tree | 300–2k (plus billboard LOD) |

The validator flags anything over budget.

## Vehicles

- Separate objects: body, glass, four wheels (`WHEEL_FL`, `WHEEL_FR`,
  `WHEEL_RL`, `WHEEL_RR`), lights (emissive), later doors and hood.
- Wheel origins at hub centers. The export script measures wheel radius and
  positions and writes them into the vehicle definition for Rapier's vehicle controller.
- A simple `-colonly` convex hull for the chassis.

## Characters & animation

- One shared humanoid skeleton for every character, so all animations work on everyone.
- Placeholder animations from Mixamo or CC0 packs until custom animation exists.
- Clothes as separate meshes on the same skeleton (swappable outfits for shops).

## Export pipeline

`npm run assets` (in `game/`) runs `game/scripts/build-assets.mjs`:

1. Every `blender/scripts/generators/gen_*.py` runs in headless Blender. Each
   builds its assets, validates them, and exports `.glb` with custom properties.
2. glTF-Transform compresses each file: meshopt geometry, deduplication
   (KTX2 textures once assets have textures).
3. Output lands in `game/public/assets/<category>/`.

Scripted assets are **build outputs**: generated locally and in CI, never
committed. Hand-authored `.blend` files will live in `blender/src/` (Git LFS) and
be exported by the same build step once the first one exists.

## Validation (runs in CI)

`blender/scripts/validate.py` checks every asset for:
- Correct name prefix and suffixes
- Applied transforms and correct origin placement
- Triangle and texture budgets
- Required child objects (wheels, collision hulls) and valid custom properties
- No missing textures, no unused materials
