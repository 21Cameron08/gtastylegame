# 06 – Blender Pipeline

Blender is the main content tool for meshes, kits, vehicles, characters, and
possibly the road layout. This doc sets the conventions so assets drop into
Godot with zero manual fixing.

## How Claude works with Blender

| Mode | How it works | Good for |
| --- | --- | --- |
| **Scripted (works today)** | Claude writes `bpy` Python scripts in `blender/scripts/`, runs them in headless Blender, and exports `.glb` straight into `game/assets/`. You open the results in your Blender to review and refine. | Modular kits, procedural props, batch export, validation, preview renders |
| **Live (optional)** | A Blender MCP add-on on your computer, used from a Claude Code session running on that same computer, lets Claude drive your open Blender scene interactively. | Iterating on a scene together in real time |

Scripted mode is the backbone either way: scripts are versioned, repeatable,
and run in CI. A smoke test (script builds a mesh with a collision hull and
exports `.glb`) already passes in the cloud environment.

**Blender version**: pin one LTS release (4.2 LTS or newer) for the whole team
and CI. Scripts target that version's API.

## Division of labor

**Scripted (generated by code):**
- Modular building kits: parametric brick storefronts, windows, cornices,
  awnings, porches, siding, roofs
- Road pieces, curbs, sidewalks, parking lots, painted lines
- Fences, power poles with sagging lines along a curve, mailboxes, signs
  (church marquee with custom text), billboards
- Vegetation scatter sets (pines, scrub, kudzu patches)
- Blockouts for vehicles, weapons, and landmark buildings
- Validation, LOD checks, batch export, preview renders

**Hand-authored (you, in Blender):**
- Hero vehicles and their detail pass
- Characters (body, clothes, faces)
- Weapons
- Landmarks: courthouse, water tower, SaveMore, megachurch, mill
- Polish passes on scripted blockouts

## Units, axes, origins

- **1 Blender unit = 1 meter.** Apply all transforms (scale 1, rotation 0) before export.
- **Up = +Z in Blender.** The glTF exporter converts to Godot's +Y up.
- **Forward**: models face **−Y** in Blender (the Front view, Numpad 1, shows
  the front). That lands as +Z in Godot, matching Godot's model-front convention.
- **Origins**:
  - Props and buildings: bottom center (sits on the ground at Z = 0)
  - Vehicles: ground level, centered between the axles
  - Wheels: hub center
  - Characters: between the feet
  - Weapons: grip point

## Godot import suffixes

Godot reads object-name suffixes on import and builds the right nodes for us:

| Suffix | Result in Godot |
| --- | --- |
| `-col` | Mesh plus a static collision body (trimesh) |
| `-convcol` | Mesh plus a convex collision shape |
| `-colonly` | Collision only, no visible mesh (use for simple hulls) |
| `-convcolonly` | Convex collision only |
| `-navmesh` | Navigation mesh |
| `-occ` / `-occonly` | Occluder (with or without visible mesh) |
| `-rigid` | Rigid body |
| `-vehicle` / `-wheel` | Vehicle body and wheels (for prototyping) |
| `-noimp` | Not imported (reference/helper objects) |
| `-loop` | Looping animation |

Rule: **collision is always simple.** Use a separate low-poly hull (`-colonly`),
never the render mesh, except for large static buildings.

## Modular grid

- Snap to a **0.5 m** grid; kit pieces are multiples of **1 m**.
- Downtown facades: **4 m** wide modules, **4.5 m** ground-floor storefronts,
  **3.5 m** upper floors.
- Houses: **3 m** floors; porches **2.5 m** deep.
- Roads: **3.5 m** lanes, **2 m** sidewalks, **15 cm** curbs.

## Materials & textures

- **Trim sheets** (2048²) for buildings: brick, siding, trim, windows, signage.
  Most of the town shares a handful of materials, so it batches well.
- **Palette texture** (256²) for props: UVs land on color swatches. Ideal for
  scripted assets and very cheap to render.
- **Vehicles**: 2048² body texture plus a shared paint material whose color is
  set per car in Godot (one mesh, many paint jobs).
- **Characters**: 2048² per character; clothes share atlases.
- PBR metallic/roughness, exported as glTF. Emissive on a separate material for
  lights and neon so they can switch on at night.

## Triangle budgets (LOD0)

| Asset | Triangles |
| --- | --- |
| Player-drivable vehicle | 20k–40k |
| Character | 10k–20k |
| Weapon | 3k–8k |
| Small building | 1k–5k |
| Landmark | up to 20k |
| Prop | 50–2k |
| Tree | 500–3k (plus billboard LOD) |

Godot auto-generates LODs on import. The validator script flags anything over budget.

## Vehicles

- Separate objects: body, glass, four wheels (`WHEEL_FL`, `WHEEL_FR`,
  `WHEEL_RL`, `WHEEL_RR`), lights (emissive), later doors and hood.
- Wheel origins at hub centers; wheel radius measured by the validator and
  written into the vehicle definition automatically.
- Simple `-colonly` hull for the chassis.

## Characters & animation

- One shared humanoid skeleton for every character, so all animations retarget
  (Godot's humanoid skeleton profile).
- Placeholder animations from Mixamo or CC0 packs until custom animation exists.
- Clothes as separate meshes on the same skeleton (swappable outfits for shops).

## Export

- Each asset or kit collection exports to one `.glb` in `game/assets/...`.
- Command pattern:
  `blender -b blender/src/<file>.blend -P blender/scripts/export.py -- <args>`
- `.blend` sources live in `blender/src/`; exported `.glb` files are committed
  too (both via Git LFS) so the game builds without Blender installed.

## Validation (runs in CI)

`blender/scripts/validate.py` checks every asset for:
- Correct name prefix and suffixes
- Applied transforms and correct origin placement
- Triangle budget
- Required child objects (wheels, collision hulls)
- No missing textures, no unused materials
